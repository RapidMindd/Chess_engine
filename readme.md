# Chess engine

Шахматный движок на C++14. Проект реализует представление позиции,
генерацию легальных ходов, оценочную функцию и поиск лучшего хода.

## Что реализовано

- представление позиции на битбордах;
- чтение позиции из FEN и запись обратно в FEN;
- выполнение и откат ходов через `makeMove` / `undoMove`, а также null move;
- генерация сразу легальных ходов (без проверки «сделать и откатить»);
- рокировка, en passant и превращения пешек;
- проверка шаха, мата и пата;
- ничьи: троекратное повторение, правило 50 ходов, недостаточный материал;
- perft для проверки генератора ходов;
- UCI-интерфейс, движок можно подключить к любому GUI или к cutechess-cli.

## Представление позиции

Позиция хранится двенадцатью битбордами (по одному на тип фигуры и цвет) плюс
массив `int8_t[64]` для быстрого ответа на вопрос «что стоит на поле». Вместе с
доской инкрементально пересчитываются:

- Zobrist-хеш позиции и отдельный хеш пешечной структуры;
- материал и piece-square tables для миттельшпиля и эндшпиля;
- фаза игры;
- счётчик полуходов для правила 50 ходов и кольцевой буфер хешей для повторений.

Благодаря этому `makeMove` сразу отдаёт готовый хеш и готовую «материальную»
часть оценки, а не пересчитывает их заново на каждом листе.

## Генерация ходов

Ходы слонов, ладей и ферзей считаются magic bitboards. Если процессор
поддерживает BMI2, вместо умножения используется инструкция `PEXT` — это
определяется на этапе компиляции.

Генератор сразу выдаёт легальные ходы. Перед генерацией один раз на узел
строится `LegalInfo`: связанные фигуры, шахующие фигуры, маска полей, на которые
можно уйти от шаха, и поля, атакованные соперником. Из-за этого проверка «а не
подставили ли короля» не нужна вообще.

В том же `LegalInfo` заранее считаются поля, с которых каждый тип фигуры даёт
шах вражескому королю, поэтому `givesCheck` для очередного хода — это пара
битовых операций, а не отдельный анализ позиции.

## Поиск

Negamax с alpha-beta отсечением, итеративным углублением и aspiration window.
Из оптимизаций поиска сейчас есть:

- transposition table и Zobrist hashing;
- principal variation search;
- quiescence search с delta pruning и отсечением проигрышных разменов по SEE;
- упорядочивание ходов: ход из таблицы, SEE + MVV/LVA, killer moves,
  counter moves, history heuristic, capture history;
- static exchange evaluation на битбордах, без make/undo;
- null move pruning с защитой от цугцванга;
- late move reductions по логарифмической таблице, с поправкой на history,
  improving и тип узла;
- late move pruning, futility pruning, reverse futility pruning, razoring;
- отсечение ходов, проигрывающих материал, по SEE;
- продление поиска на шахах;
- mate distance pruning;
- internal iterative deepening, когда хода из таблицы нет;
- Lazy SMP: несколько потоков ищут одну позицию через общую таблицу.

Шахи никогда не отсекаются: жертва с шахом — это ровно тот ход, который SEE
оценивает хуже всего, а матовой атаке нужен больше всего.

Поиск можно ограничить глубиной, временем или количеством узлов.

## Таблица транспозиции

Таблица фиксированного размера: четыре записи в бакете, замещение по глубине с
учётом возраста записи. Каждый слот — пара 64-битных слов `key ^ data` и `data`,
поэтому запись из другого потока не может быть прочитана наполовину (lockless
hashing по Хайатту): испорченная пара просто не пройдёт проверку ключа.

Матовые оценки хранятся относительно узла, в котором были найдены, и
пересчитываются при чтении — иначе одна и та же запись давала бы разное
расстояние до мата на разной глубине.

Отдельно в проекте лежит собственная хеш-таблица Robin Hood hashing на
собственном `Vector`. Она больше не используется внутри transposition table:
таблице поиска нужен фиксированный размер и замещение, а не рост и рехеш.
Структура и её тесты остались в проекте как самостоятельная реализация.

## Оценка позиции

Оценка tapered: отдельно считается миттельшпильная и эндшпильная оценка, и они
смешиваются по фазе игры. В неё входят:

- материал и piece-square tables (значения PeSTO), инкрементально;
- мобильность, без учёта полей под боем вражеских пешек;
- пешечная структура (сдвоенные, изолированные, отсталые, проходные пешки)
  с кешем по пешечному хешу;
- пара слонов;
- ладьи на открытых и полуоткрытых линиях;
- безопасность короля: пешечный щит, открытые линии рядом с королём и вес
  фигур, атакующих поля вокруг короля;
- темп.

Оценка возвращается в сотых долях пешки. Например, `0.35` означает небольшой
перевес белых, а `-1.20` — перевес черных примерно на пешку с небольшим.

## Сборка и запуск

```bash
make            # bin/main
make run        # игра из консоли, ходы вида e2-e4
make test       # юнит-тесты
make bench      # прогон тестовых позиций
make perft      # проверка генератора ходов
make uci        # UCI-режим
make selfplay   # движок играет сам с собой
make release    # переносимая сборка, без -march=native
```

Параметры передаются через переменные make:

```bash
make bench DEPTH=14 THREADS=8
make perft ARGS=6
make run ARGS="10 1000"      # глубина 10, 1000 мс на ход
make selfplay ARGS="8 4"
```

`make bench` печатает время, число узлов и NPS; `make perft` сверяет число
листьев с известными значениями.

## Замеры

Машина: Ryzen 7 8840HX, один поток, три позиции из старого бенчмарка.
Время до заданной глубины:

| глубина | было    | стало  | во сколько раз |
|---------|---------|--------|----------------|
| 10      | 1.12 с  | 0.06 с | 20             |
| 12      | 4.17 с  | 0.12 с | 34             |
| 14      | 15.91 с | 0.29 с | 55             |

За те же 16 секунд, за которые старая версия доходила до глубины 14, новая
доходит до глубины 22, то есть на 8 полуходов глубже.

Матчи между старой и новой версией: на 150 мс на ход новая выиграла 23 партии
из 24 при одной ничьей; даже с форой по времени в 40 раз (25 мс против 1000 мс)
она набрала 81%.

Lazy SMP на восьми потоках даёт примерно пятикратный NPS и сокращает время до
заданной глубины почти втрое:

```bash
make bench DEPTH=18 THREADS=1   # ~5.7 с
make bench DEPTH=18 THREADS=8   # ~2.0 с
```
